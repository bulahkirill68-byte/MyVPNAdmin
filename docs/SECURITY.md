# Безопасность

- Доступ по SSH-tunnel, HTTP только на локальном loopback; защищённый SSH несёт запросы до VPS. Cookie HttpOnly, SameSite=Strict, 8 часов. Secure=false нужен для локального HTTP; для отдельного действительного TLS reverse proxy устанавливается COOKIE_SECURE=true. Публичный reverse proxy в комплект не входит.
- Администратор создаётся только интерактивным CLI. Пароль 14–256 символов, Argon2id (64 МиБ, 3 итерации, parallelism=2). Нет пароля по умолчанию, first-run HTTP регистрации или секретов в .env.
- Сессионные и subscription токены генерируются secrets.token_urlsafe(48); в БД только SHA-256. CSRF — отдельный случайный токен сессионной записи и заголовок X-CSRF-Token. При смене UUID, аннулировании или удалении subscription token отзывается.
- Глобально 5 неверных входов → пауза 15 минут, счётчики переживают рестарт. Это небольшой локальный single-admin MVP; глобальный лимит выбран намеренно. События неудачных/удачных входов и значимых действий аудируются. Роль — владелец, TOTP не реализован.
- Проверка Host и Origin, CORS закрыт, CSP, запрет iframe, no-referrer, nosniff, no-store. API/OpenAPI доступен после входа. Uvicorn access log выключен, чтобы URL подписки не попадал в журнал. Аудит не содержит VLESS URL, UUID, паролей или token. Чтение карточки доступа аудируется.
- Контейнеры UID 10001, read_only, tmpfs /tmp, cap_drop ALL, no-new-privileges. Хостовый root используется только администратором для подготовки папок/чтения config при одноразовом экспорте. Xray config не монтируется ни в один сервис. Публичных management API, Docker socket, privileged или root-контейнеров нет.
- UUID в БД — реальный секрет доступа, хранится открыто ради восстановления Xray. Приватного REALITY-ключа в БД нет. Хеширование UUID сделало бы reconciliation невозможным; защищайте /data правами 0700 и копии 0600. Хеши токенов не превращают всю базу в несекретную.

## Изменение глобальных параметров Xray

В UI только просмотр. Если нужно изменить глобальную настройку: SSH root → сохранить config.json в защищённый backup → создать временный файл в той же файловой системе → `xray run -test -config ВРЕМЕННЫЙ_ФАЙЛ` → атомарный rename с сохранением владельца/прав → контролируемый restart → проверка службы и подключения. При ошибке вернуть backup и перезапустить. Это отдельное обслуживание с возможным разрывом VPN; панель не запускает его автоматически.

## Границы блокировки

RemoveUser влияет на новые подключения, но не гарантирует закрытие открытых. При сбое worker/API enforcement задерживается. Статические UUID возвращаются из config при рестарте Xray до reconciliation; применённая ротация снимает известный старый UUID при следующем проходе. Абсолютный fail-closed для статического клиента этим MVP не обеспечивается. Не меняйте UUID/email в config параллельно с панелью без согласования состояния.
