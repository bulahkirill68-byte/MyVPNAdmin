# Вход из браузера без SSH и без домена

По умолчанию панель остаётся локальной. По явному выбору администратора можно включить публичный **HTTPS на отдельном порту** с действительным IP-сертификатом Let’s Encrypt. Xray TCP 443 остаётся прежним.

```bash
sudo bash scripts/enable_https.sh ВАШ_ПУБЛИЧНЫЙ_IP 8443
```

Откройте `https://ВАШ_ПУБЛИЧНЫЙ_IP:8443`. Аккаунт администратора и пароль прежние. HTTP на 80 используется для ACME-проверки и перенаправления на HTTPS; публичной HTTP-формы входа нет. Вход разрешён только для указанного Host, POST защищён проверкой Origin и CSRF. В браузере должны отсутствовать предупреждения о сертификате — self-signed fallback не предусмотрен.

Скрипт на Ubuntu-хосте устанавливает изолированный Certbot >=5.4, запрашивает IP-сертификат с профилем `shortlived`, добавляет собственные конфиги Nginx и открывает 80/8443 в активном UFW. Внешний firewall провайдера тоже должен пропускать эти порты. Приватные TLS/ACME ключи остаются в `/etc/reality-control/acme`; Docker их не получает. Nginx проксирует только в `127.0.0.1:8000`, backend доверяет forwarded headers только от 127.0.0.1. `PUBLIC_ORIGIN` задаёт разрешённый публичный Host, cookie становится Secure/HttpOnly/SameSite=Strict. На `/api/login` действует дополнительный per-IP rate limit.

## Продление и закрытие при проблемах сертификата

IP-сертификат действует около 160 часов, поэтому настроены два systemd timer:

- `reality-public-renew.timer`: проверка продления каждый час и загрузка нового сертификата Nginx;
- `reality-public-guard.timer`: проверка срока, IP SAN, соответствия ключа и доверенной цепочки каждые пять минут.

При отсутствии, недоверенности или остатке срока менее часа контроллер убирает только собственный HTTPS vhost и перечитывает Nginx. HTTP-логин не включается. Перед стартом Nginx выполняется та же проверка, чтобы не публиковать просроченный сертификат после перезагрузки. При восстановлении действительного сертификата HTTPS автоматически возвращается.

```bash
systemctl list-timers 'reality-public-*'
journalctl -u reality-public-renew -u reality-public-guard --no-pager -n 60
/opt/reality-certbot/bin/certbot renew --dry-run \
  --config-dir /etc/reality-control/acme \
  --work-dir /var/lib/reality-acme --logs-dir /var/log/reality-acme
python3 /opt/reality-public/https_control.py refresh
```

Повторный запуск `enable_https.sh` с тем же IP/портом обновляет host-side инструменты и сохраняет действующий сертификат, пока он не требует продления. Изменения обычных пользователей по-прежнему проходят через локальный Xray gRPC. Публичные подписки `/sub/` этим режимом не включаются.

## Если адрес недоступен без другого VPN

HTTPS устраняет необходимость SSH-туннеля и зависимость от TCP 22. Но если провайдер блокирует весь IP/маршрут до VPS, один лишь другой порт этого не исправит. Проверяйте ссылку с домашнего интернета и мобильной сети. В этом случае нужен доступный маршрут к VPS, смена его IP у провайдера либо отдельно согласованный внешний gateway.

Официальная поддержка IP-сертификатов Certbot: <https://letsencrypt.org/2026/03/11/shorter-certs-certbot/>.
