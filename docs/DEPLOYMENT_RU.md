# Установка, обновление и восстановление

## Перед запуском

1. Убедитесь, что существующий VPN работает: `systemctl is-active xray`; не запускайте установщик Xray повторно.
2. Установите Docker Engine и Compose plugin для Ubuntu: <https://docs.docker.com/engine/install/ubuntu/>. Нужен Linux host network.
3. Склонируйте репозиторий, выполните `sudo bash scripts/install.sh`.
4. Создайте администратора `docker compose exec web python -m app.cli admin`.
5. Выполните read-only импорт по README. Установщик пользователя уже создаёт нужный email/stats/API. Скрипт экспортирует только метаданные и UUID, передаёт JSON через stdin. Не сохраняйте этот JSON в Git.

Если конфиг содержит JSONC, комментарии или trailing commas, stdlib JSON экспорт отклонит его. Подготовьте локальную валидную JSON-копию и укажите `--config` вместо редактирования работающего файла. Если нет стабильных email/StatsService, требуется отдельная ручная настройка хоста с backup и тестом; автоматической небезопасной миграции нет.

## Доступ

`ssh -N -L 8000:127.0.0.1:8000 root@IP` с вашего компьютера → <http://localhost:8000>. Не используйте публичный IP:8000. Не добавляйте ports в Compose. 10085 не должен быть опубликован ни Docker, ни Xray. SSH можно выполнять от своего sudo-пользователя вместо root.

## Приёмка на действующем VPS

Это обязательная реальная проверка администратора после установки; локальные unit tests не подтверждают совместимость установленного Xray.

1. До импорта убедитесь, что первый клиент подключается. Сохраните root-only backup config.json отдельно, запишите вывод `xray version`.
2. `bash scripts/diagnose.sh`: ожидается active Xray, слушатели 443, **127.0.0.1:8000** и **127.0.0.1:10085**, здоровые контейнеры. `app.cli smoke` должен получить uptime StatsService.
3. С другого компьютера проверьте отсутствие доступа к `http://IP:8000` и TCP IP:10085. `curl` с VPS по loopback должен успешно открыть health. 443 — доступен согласно прежним firewall правилам.
4. Импортируйте сервер. В UI первый пользователь имеет прежние UUID и email; после 15 секунд применение должно стать «Применено». Если ошибка GetInboundUsers — не игнорируйте её, проверьте совместимость версии. Первое VPN-подключение должно продолжать работать.
5. Создайте тестового пользователя, дождитесь applied, откройте QR/ссылку и импортируйте в v2rayNG/v2rayN. Проверьте реальный интернет через этот узел.
6. Передайте трафик и дождитесь роста used_bytes и графика. Если нет счётчиков, проверьте policy.levels[0], email и StatsService. Нулевой трафик без подключения нормален.
7. Поставьте короткий срок UTC или небольшую квоту, дождитесь expired/quota_exceeded. Закройте клиентское соединение и проверьте, что **новое** не устанавливается. Открытую сессию API может не оборвать.
8. Продлите срок/увеличьте квоту, возобновите доступ, дождитесь applied и повторно подключитесь.
9. Проверьте backup/restore на тестовом пользователе. Restore откатывает всю БД, включая доступы, и сбрасывает сессии.
10. В согласованное окно обслуживания перезапустите хостовый Xray и проверьте reconciliation нового UUID и блокировок. Перезапуск сам по себе прерывает VPN; для обычного CRUD он не нужен.

## Обслуживание

```bash
docker compose ps
docker compose logs --tail=100 web worker
bash scripts/diagnose.sh
df -h ./data
```

Health web проверяет SQLite, health worker — свежесть итерации. Здоровый worker при недоступном Xray возможен: подробное состояние API смотрите в панели. При остановке worker новые квоты/сроки не применяются до его восстановления. `POLL_SECONDS` минимум 5 секунд, по умолчанию 15; после изменения `.env` пересоздайте worker.

Обновление `bash scripts/update.sh`: согласованный backup → git pull --ff-only → build → остановка web/worker → миграция → запуск. Xray и 443 не затрагиваются. Если build упал, старые контейнеры продолжают работать; если миграция упала после остановки, устраните причину или восстановите backup и предыдущую версию кода. Не используйте `down -v`.

## Backup / restore

`bash scripts/backup.sh` или кнопка в настройках. Автокопии раз в сутки при работающем worker, не более 14. `/data/backups` внутри контейнера = `./data/backups` на VPS. Локальные копии не спасают от потери VPS: скопируйте их по SSH на свой компьютер и защищайте как VPN-секреты.

```bash
sudo ls -l data/backups
bash scripts/restore.sh panel-ЧИСЛО.sqlite3
# Подтверждение: RESTORE
```

Скрипт останавливает web/worker, получает worker lock, проверяет SQLite integrity и таблицы, делает аварийную копию нынешней БД, восстанавливает backup через SQLite API, сбрасывает admin-сессии, применяет миграции и запускает сервисы. Восстановление не вызывает restart Xray, но worker приведёт runtime к восстановленному желаемому состоянию. Если скрипт упал, сервисы могут остаться остановленными: проверьте вывод и место на диске, затем осознанно повторите или `docker compose up -d`.

Автоматический backup содержит только панель. Xray config и защищённые root access-файлы резервируйте отдельно по прежней процедуре. Restore из недоверенного файла не выполняйте.

## Ручная выдача доступа

```bash
docker compose exec -T web python -m app.cli subscription ID_ПОЛЬЗОВАТЕЛЯ
```

Команда выводит VLESS URI активного пользователя в ваш SSH-терминал. Это секрет, используйте приватный канал. Для получения base64 подписки создайте локальный token в карточке доступа и откройте URL через SSH-туннель; телефон без туннеля к localhost VPS доступа не имеет.
