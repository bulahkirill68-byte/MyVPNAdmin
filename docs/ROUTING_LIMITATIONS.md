# Маршрутизация и возможности клиентов

Есть четыре **разных** объекта:

1. Серверное состояние Xray: UUID/email/flow, допуск новых подключений.
2. Подписка на узлы: VLESS ссылки, без гарантий обновления routing/per-app.
3. Клиентские Xray routing rules: отдельный экспорт JSON и ручной импорт.
4. Android Per-app proxy: выбор приложений локально в v2rayNG, не меняется сервером.

## Приоритеты

Экспорт объединяет локальные исключения → шаблон индивидуальных правил → глобальные правила → базовый пресет. Для каждого устройства в карточке назначается ru-direct/all-proxy/custom; кнопка экспорта в карточке выдаёт этот пресет с правилами. В MVP редактор индивидуального слоя — **общий шаблон**, а не отдельная редактируемая коллекция на каждого пользователя. Локальные правила в редакторе — подготовленный для клиента слой; панель не читает локальную конфигурацию телефона.

Базовый ru-direct/custom:

1. Явные исключения proxy перед остальными правилами.
2. `geoip:private` → direct.
3. localhost, .lan, .local, home.arpa → direct.
4. `geosite:category-ru`, .ru, .su, .рф (`xn--p1ai`) → direct.
5. `geoip:ru` → direct.
6. TCP/UDP → proxy.

all-proxy добавляет после явно заданных правил только TCP/UDP → proxy. В JSON критерии domain и ip никогда не смешиваются в одном правиле. Первый match выигрывает.

## Экспорт и импорт

Экспорт редактора — объект Xray routing `{domainStrategy:"IPOnDemand",rules:[...]}` для v2rayNG/v2rayN. В карточке пользователя отдельно доступен **полный клиентский JSON** с узлом, outbounds, DNS и sniffing. Клиентские версии используют разные форматы сохранения/импорта: полный JSON загружайте как custom configuration, объект routing — в редактор правил; если клиент ожидает собственный формат, перенесите правила вручную.

Используются теги proxy/direct/block (в полном JSON они уже определены). Проверьте версии geoip.dat/geosite.dat и наличие category-ru, DNS и IPv6 (GeoIP должен включать IPv6). При отсутствии требуемой Geo-базы конфигурация клиента может не пройти проверку; обновите базы либо замените Geo-критерии явными сетями/доменами. Sniffing помогает доменным правилам, но не восстанавливает любой домен из IP. IPOnDemand разрешает домен при проверке IP-критерия; IPIfNonMatch с финальным catch-all не обеспечивает GeoIP для каждого домена. Полный JSON использует HTTPS DNS Cloudflare, вызываемый локально вне прокси, чтобы исключить рекурсивную маршрутизацию DNS; DNS-провайдер видит запросы, хотя транспорт шифрован. При блокировке этого DoH нужно выбрать другой доверенный DNS в клиенте.

Редактор поддерживает порядок drag-and-drop и стрелками, импорт объекта routing/rules. Правила с неизвестными outboundTag и одновременными domain+ip отклоняются; проверьте клиентские расширенные поля вручную — MVP импортирует только domain/ip/outboundTag. Значения regexp допускаются в экспорте, но не исполняются веб-тестером из-за риска тяжёлых регулярных выражений.

Тест маршрута **предварительный**: на сервере нет клиентских GeoIP/GeoSite/DNS. Если ранее могло совпасть геоправило, результат помечается approximate, а не выдаётся за точный. Окончательная проверка — в установленном клиенте.

Чтобы исключить российские Android-приложения, откройте Per-app proxy и настройте выбор/исключение приложений вручную. Ни серверный routing, ни обычная подписка vless:// не гарантируют автоматического применения этих исключений. Собственного VPN-клиента в проекте нет.
