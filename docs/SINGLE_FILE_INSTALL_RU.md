# Один файл установки Reality Control

`install-reality-control.sh` — самораспаковывающийся Bash-пакет. Внутри находятся **исходники всей панели**: backend, frontend, миграции, Dockerfile/Compose, host-agent, встроенный установщик Xray, HTTPS/ACME-компонент, тесты и документация. Не требуется клонировать репозиторий или передавать GitHub-токен новому VPS.

Пакет основан на коде действующей серверной установки. Рабочая база SQLite, пароли, сессии, токены подписок, пользовательские UUID, приватный REALITY-ключ и действующие TLS-сертификаты **не входят в установщик**. Новый сервер получает собственные секреты и собственный IPv4.

## Запуск

1. Скачайте **install-reality-control.sh** из GitHub через **Download raw file** и скопируйте на новый VPS. Репозиторий приватный, поэтому скачивание требует входа в GitHub; не используйте неавторизованный `curl` приватного Raw URL.
2. Ubuntu Server 22.04 / 24.04 / 26.04, root/sudo, systemd. Нужен доступ к Интернету и портам провайдера: 80 для ACME, 8443 для панели, 443 для VPN. Второй VPS и домен не нужны.
3. Выполните:

```bash
sudo bash install-reality-control.sh
```

Установщик:

- определит **публичный IPv4 именно этого VPS** — по согласованным ответам HTTPS-сервисов; при недоступности сервисов допускается единственный глобальный IPv4 интерфейса;
- установит Docker Engine + Compose plugin из официального Docker-репозитория, если Docker отсутствует; существующий Engine не заменяет;
- развернёт панель в `/opt/reality-control`, создаст `/data` с UID/GID 10001, host-agent, миграции и web/worker;
- создаст первого администратора со случайным паролем, выведет его в SSH-терминал и сохранит в `/root/reality-control-admin.json` с правами 0600;
- настроит **https://ОПРЕДЕЛЁННЫЙ_IP:8443**, действительный IP-сертификат Let’s Encrypt и автоматическое продление;
- передаст IPv4 в `.env` как `PANEL_PUBLIC_IP`: мастер Xray сразу откроется с заполненным адресом;
- сохранит генерацию **`fp=firefox`** в VLESS/QR и **`"fingerprint":"firefox"`** в клиентском JSON.

На чистом сервере откройте раздел **Настройки → Установка и подключение Xray**, нажмите установку ядра и импорт. Адрес уже заполнен.

### Сразу установить и Xray

```bash
sudo bash install-reality-control.sh --with-xray
```

Если ядро отсутствует, создастся новая VLESS + REALITY конфигурация с собственными UUID/ключами. После этого первый пользователь автоматически импортируется в SQLite. Работающее ядро и существующий конфиг этим параметром не заменяются.

## Параметры

```bash
# Явный публичный адрес при NAT, нескольких IP или недоступных сервисах определения:
sudo bash install-reality-control.sh --ip ВАШ_IP

# Другой свободный HTTPS-порт:
sudo bash install-reality-control.sh --https-port 9443

# Другой SNI/target только для новой установки ядра:
sudo bash install-reality-control.sh --with-xray --sni www.wikipedia.org

# Новая локальная установка без публичного HTTPS:
sudo bash install-reality-control.sh --local-only

# Явно разрешить подготовку существующего legacy Xray без API/stats/email:
sudo bash install-reality-control.sh --prepare-existing

# Только проверить целостность и распаковать в пустой каталог (без root, apt и сервисов):
bash install-reality-control.sh --extract-only ./reality-source
```

При автоматическом определении не выбирается адрес старого сервера из пакета. Если ответы сервисов противоречат друг другу, установка остановится с предложением `--ip`. При нескольких IP/NAT администратор может указать адрес, на который действительно приходят клиентские подключения.

Существующий полностью подготовленный Xray импортируется без изменения ключей/UUID. Старый конфиг без API/statistics/email по умолчанию остаётся для подготовки через UI. `--prepare-existing` явно разрешает backup → test → атомарную замену → один restart → проверку/rollback. Срок доступа Xray не хранит, поэтому первоначальный импорт бессрочный, затем задайте нужные условия в панели.

## Повторный запуск и обновление

Скачайте новый `install-reality-control.sh` и запустите повторно. Сохраняются `data`, `.env`, администратор и его пароль. Перед обновлением создаются согласованная SQLite-копия и архив предыдущих исходников в `/var/backups/reality-control-install/` (0600). Сборка выполняется до остановки web/worker. Обычный запуск Xray не перезапускает; `down -v` не используется.

Изменённые вручную исходники пакета не перезаписываются: их хеши сравниваются с предыдущим manifest. Неизвестная непустая папка или symlink `.env`/`data` отклоняются. Пользовательские файлы вне manifest сохраняются.

Чистая Git-установка также может перейти на пакетное обновление: `.git` сохраняется, а дальнейшее управление исходниками выполняется новым установщиком. `scripts/update.sh` распознаёт пакет и подсказывает повторный запуск одного файла вместо `git pull` по смешанному дереву.

Если сборка падает, прежние контейнеры продолжают работать. При ошибке миграции после остановки нужно разобраться с выводом или восстановить предыдущую версию и SQLite-копию. Ошибка выдачи HTTPS-сертификата не превращает панель в публичный HTTP: локальная панель остаётся доступна через SSH-туннель, исправьте доступность ACME/HTTPS портов и повторите установку. Защищённый файл нового администратора остаётся на VPS.

## Проверка пакета и пересборка

Встроенный SHA-256 проверяет целостность payload, `BUNDLE-MANIFEST.json` — состав и хеш каждого файла. Распаковка не допускает symlink/hardlink, абсолютные пути, `..`, дубликаты и посторонние файлы. Эти хеши защищают от повреждения, а источник установщика должен быть доверенным — ваш GitHub.

`--check` сверяет код shell-обёртки, состав пакета, manifest и каждый байт исходников. Разные версии zlib/Python могут сжать одинаковый tar немного по-разному, поэтому сравниваются исходные данные, а не только сжатые байты.

```bash
python scripts/build_installer.py
python scripts/build_installer.py --check
bash -n install-reality-control.sh
bash install-reality-control.sh --extract-only /tmp/reality-source-check
```

**Один файл не означает офлайн-установку:** apt, Docker base images, npm/Python-зависимости, Certbot и официальный Xray скачиваются из Интернета. Проверки нового пустого Ubuntu-хоста не заменяются одним лишь синтаксическим тестом; доступность Docker/ACME репозиториев и внешнего firewall зависит от VPS.
