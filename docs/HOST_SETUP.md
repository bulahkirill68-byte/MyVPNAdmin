# Установка Xray из панели

## Чистый VPS

1. Ubuntu 22.04/24.04/26.04, Docker Engine + Compose plugin. TCP 443 свободен.
2. `sudo bash scripts/install.sh`: ставит локальный host-agent, готовит data, собирает и запускает панель.
3. `docker compose exec web python -m app.cli admin`: создайте администратора.
4. Откройте SSH-туннель и localhost:8000, войдите, перейдите в **Настройки → Установка и подключение Xray**.
5. Укажите публичный IPv4 и сторонний HTTPS target/SNI. Подтвердите установку, нажмите **Установить Xray + REALITY**.
6. Дождитесь «Готово», нажмите **Импортировать в панель**. Первая запись получит исходный UUID из только что созданного конфига.
7. В пользователях создавайте доступы; по умолчанию профиль «Россия напрямую». Для маршрутизации на устройстве выдавайте **полный клиентский JSON**.

Встроенный `host/install_xray_reality.sh` основан на предоставленном установщике: официальный XTLS/Xray-install, тест TLS target, UUID/X25519/Short ID, XTLS Vision, localhost API и пользовательская статистика. Задача выполняется асинхронно на хосте, не в контейнере. Существующая конфигурация или установленный бинарник блокируют fresh install. Нет режима replace/удаления/произвольного shell. Firewall автоматически не меняется: разрешите TCP 443 в правилах провайдера при необходимости.

## Существующий сервер

Кнопка **Подготовить существующий Xray** добавляет отсутствующие email/API/stats, сохраняя UUID, REALITY ключи, shortIds, transport, порт, routing/outbounds. Сначала backup `/var/backups/reality-agent/config-*.json` 0600, затем `xray run -test`, атомарная замена, restart и проверка API. При ошибке службы возвращается оригинальный файл и запускается исходная конфигурация. Если поля уже настроены, повторная подготовка ничего не перезапускает.

Срок действия невозможно прочитать из Xray config: он там не хранится. При первоначальном импорте доступ бессрочный; задайте нужный срок/квоту в UI. Повторный импорт уже подключённого Server отклоняется, чтобы не затереть SQLite.

## Почему нужен bootstrap на хосте

Обычный non-root контейнер не имеет права устанавливать systemd-ядро на Ubuntu. `install.sh` устанавливает небольшой root systemd bridge в `/opt/reality-agent`, который принимает только фиксированные команды на `/run/reality-agent/control.sock` (root:10001, 0660, каталог 0750). SO_PEERCRED допускает только UID 0/10001. Web монтирует каталог сокета read-only; config.json, /root и Docker socket не монтируются. Приватный REALITY-ключ не передаётся в web; публичный вычисляется на хосте через X25519.

Для ранее установленной панели выполните один раз `sudo bash scripts/install_agent.sh`, затем обновите Compose. После этого будущие установки ядра/подготовка запускаются через UI. Агент — привилегированная доверенная часть установки; возможность управления им выдаётся процессам UID 10001 на этом VPS.

Диагностика: `systemctl status reality-agent`, `journalctl -u reality-agent --no-pager -n 50`, `ls -l /run/reality-agent/`, `docker compose logs --tail=50 web`. Полное состояние задачи хранится в root-only `/var/lib/reality-agent/job.json`. При рестарте агента во время установки задача помечается прерванной; проверьте состояние Xray перед повтором. Автообновления ядра через агент пока нет, это отдельное обслуживание.
