# Reality VPN

Собственный клиент для **VLESS TCP/RAW + REALITY + XTLS Vision**. Windows: Electron/Vue и официальный Xray. Android: нативный Java UI, AndroidLibXrayLite и системный `VpnService`. Fingerprint по умолчанию — **firefox**; значение из импортированной ссылки сохраняется.

## Готовые приложения

Скачать EXE и APK на GitHub: [Reality VPN 1.0.3](https://github.com/bulahkirill68-byte/MyVPNAdmin/releases/tag/clients-v1.0.3). В релизе также опубликованы отдельные APK Android 8 и `SHA256SUMS.txt`.

Файлы локальной сборки находятся в `vpn-client/releases/`:

| Платформа | Файл | Назначение |
| --- | --- | --- |
| Windows x64 | `windows/RealityVPN-1.0.3-portable.exe` | Запуск без установки, с быстрым повторным запуском |
| Windows x64 | `windows/RealityVPN-1.0.3-setup.exe` | Установщик с выбором папки |
| Android 8.0+ | `android/RealityVPN-1.0.3.apk` | Подписанная release-сборка: arm64, armv7, x86_64 |

Отдельный порт с целевой версией **Android 8.0.0 / API 26** находится в [`android-8/`](android-8/README.md). Его универсальный APK: `android-8/releases/RealityVPN-Android8-1.0.3.apk`. Там же находятся сборки для ARM32, ARM64, x86 и x86_64 и отдельные контрольные суммы.

SHA256 и размеры: `releases/checksums.json`. Снимок интерфейса Windows: `releases/windows/screenshot.png`.

Windows 1.0.1 исправляет вставку и копирование VLESS-ссылок с асинхронным Clipboard API Electron. Перед запуском новой версии закройте старую; сохранённые профили остаются доступны.

Windows 1.0.3 добавляет **Настройки → Запуск приложения → Запускать при входе в Windows**. Переключатель выключен по умолчанию и применяется сразу, без кнопки «Сохранить». Он открывает приложение при входе текущего пользователя; VPN подключается кнопкой питания. Для portable в автозапуск записывается путь к исходному EXE: оставьте его в постоянной папке и включите переключатель заново после перемещения файла или перехода на новый EXE. Установленная версия использует путь установленного приложения. Выключение переключателя удаляет запись автозапуска Reality VPN.

Windows 1.0.2 ускоряет portable: файлы распаковываются один раз в `%LOCALAPPDATA%\RealityVPNClient\portable\<версия-хеш>`, повторные запуски используют тот же каталог. Загрузчик не устанавливает приложение и не меняет сетевые настройки. Первая распаковка каждой новой сборки занимает дополнительное время; её прерывание не помечает кэш готовым. Профили по-прежнему хранятся отдельно в каталоге пользователя.

Замер на рабочем ПК в этой сессии: старый portable 1.0.1 — 22,8 с при каждом запуске; новый 1.0.2 — 8,9 с при первой распаковке и 0,36 с при повторном запуске до готового интерфейса. Из дистрибутива также убраны неиспользуемые языковые пакеты Electron и дублирующие UI-библиотеки. Это локальный замер, не гарантия времени на любом ПК. Подготовка локального proxy-ядра в smoke-тесте заняла около 0,2 с; реальное TUN/UAC-подключение в ограниченной сети не измерялось.

Android 1.0.1 добавляет явную кнопку «Подключить VPN» и векторный значок питания вместо шрифтового символа. Нижняя навигация использует четыре равные вкладки со значками над подписями. APK подписан тем же ключом: устанавливайте поверх 1.0.0, чтобы сохранить профили.

Android 1.0.2 добавляет анимацию подключения, пульсацию активного туннеля, плавное обновление счётчиков, скорости и суммарный трафик в интерфейсе и уведомлении, постоянное уведомление с кнопкой отключения, плитку Quick Settings и значки приложений. Служебные пакеты без значка в меню скрыты. Обновление подписано прежним ключом: устанавливайте поверх существующего приложения.

Android 1.0.3 исправляет несогласованность DNS и direct-маршрутизации, обнаруженную при разборе `ERR_CONNECTION_CLOSED` на `ya.ru`/`yandex.ru`. Если включён обход РФ, DNS российских доменов идёт напрямую через DNS физической сети, с резервными резолверами Яндекса, а не через зарубежный VPN. Добавлен полный набор `geosite:yandex`; доменные правила проверяются раньше IP-правил. Для direct-выхода явно используется встроенный DNS Xray. После обновления отключите/включите VPN и полностью перезапустите браузер, чтобы не использовать старые DNS-записи и соединения. Проверка на конкретном телефоне и его сети всё ещё необходима.

Бинарники и зависимости исключены из Git. В репозитории нет ваших серверных UUID и приватных ключей. APK подписан локальным ключом приложения; Windows EXE пока без Authenticode-подписи.

## Начало работы

### Windows

1. Запустите portable EXE или установите приложение через setup EXE.
2. Откройте **Мои серверы → Добавить**, вставьте VLESS-ссылку из панели.
3. Выберите сервер и режим на экране **Подключение**:
   - **Прокси** — SOCKS5 на `127.0.0.1:10808` и HTTP на `127.0.0.1:10809`. По умолчанию приложение включает системный WinINET-прокси для текущего пользователя. Его используют браузеры и другие приложения, поддерживающие системный прокси; произвольный UDP-трафик этим режимом не перехватывается.
   - **VPN / TUN** — виртуальный адаптер, IPv4/IPv6-маршруты и необязательный WFP-фильтр DNS. Подтвердите UAC от имени того же Windows-пользователя. Пароль другой административной учётной записи не поддерживается для расшифровки DPAPI-сессии.
4. Нажмите кнопку питания. Индикатор показывает отдельно запуск ядра и доступ через сервер:
   - Анимация и этап подготовки — запуск ядра, ожидание UAC или настройка прокси.
   - «Туннель запущен · проверяем доступ» — локальный HTTP-порт готов, параллельно выполняется проверка HTTPS через этот прокси.
   - Зелёный «Доступ через VPN подтверждён» — хотя бы один из двух проверочных адресов ответил HTTPS 204 через сервер; рядом показывается время запроса.
   - Жёлтый «Нет подтверждения доступа» — локальное ядро работает, но проверочные запросы не прошли. Можно повторить проверку кнопкой; автоматически она повторяется через 5 с. Успешное соединение перепроверяется каждые 12 с и после выхода Windows из сна.
5. Для остановки нажмите кнопку повторно. Закрытие приложения также останавливает ядро и восстанавливает принадлежащий ему системный прокси.

Порты, исходящий интерфейс, российские direct-правила и дополнительные доменные правила находятся в **Настройках**. Их можно менять после отключения. Когда автоматический системный прокси выключен, задайте HTTP/SOCKS-адрес в нужной программе самостоятельно.

Проверка использует `cp.cloudflare.com/generate_204` и `www.gstatic.com/generate_204`, всегда через локальный HTTP-прокси и явные proxy-правила. Проверяется TLS-сертификат и HTTP 204; перенаправления на страницу авторизации не считаются успехом. Общий таймаут — 4,5 с, он не задерживает запуск ядра. Блокировка обоих проверочных адресов тоже приведёт к жёлтому статусу; зелёный статус подтверждает доступ к ним, а не доступность любого сайта или перехват трафика конкретного приложения.

Счётчики показывают трафик outbound `proxy`, не включая российский/LAN direct-трафик. Используется один постоянный gRPC-канал; обновление — раз в секунду. Временная ошибка статистики не отключает VPN и не обнуляет значения: показываются последние данные с пометкой задержки. Дополнительно отображается скорость получения/отправки; анимации учитывают настройку уменьшения движения в Windows.

Прокси восстанавливается только если в Windows всё ещё указан адрес, выставленный этим клиентом. Изменённая другой программой настройка сохраняется. После аварийного завершения Windows восстановление прокси выполняется при следующем запуске клиента. Не запускайте одновременно несколько клиентов, меняющих системный прокси или TUN-маршруты.

### Android

1. Перенесите APK на телефон, разрешите установку из выбранного источника и установите.
2. В разделе **Серверы** импортируйте VLESS-ссылку и выберите профиль.
3. В разделе **Приложения** выберите режим:
   - **Все приложения** — весь трафик приложений через VPN, с учётом доменных/IP direct-правил.
   - **Только выбранные — через VPN** — отметьте хотя бы одно приложение.
   - **Выбранные — без VPN** — отмеченные приложения обходят VPN.
4. На главном экране нажмите кнопку питания и подтвердите системное разрешение VPN. Разрешите уведомления, чтобы видеть активный сервис и кнопку отключения.
5. Отключите VPN на главном экране или в уведомлении. Изменения выбора приложений применяются после переподключения.

Выбор приложений реализован настоящими `VpnService.Builder.addAllowedApplication` / `addDisallowedApplication`. Собственный UID клиента всегда остаётся вне VPN, чтобы исходящие сокеты Xray не попадали обратно в туннель. В списке показаны включённые приложения с доступом к интернету и launcher-значком, включая предустановленные браузеры. Фоновые службы, оверлеи и библиотеки без launcher-активности скрыты. Для скрытых пакетов, выбранных в старой версии, появится отдельная кнопка «Убрать скрытые из выбора»: остальные выбранные приложения сохранятся. `QUERY_ALL_PACKAGES` оставлен для работы с прежними сохранёнными пакетами.

**Трафик и анимации.** На главном экране отображаются «Получено», «Отправлено» и скорости за текущий сеанс. Те же значения находятся в уведомлении, подробности доступны при его раскрытии. Счётчики обновляет только VPN-служба, раз в секунду: AndroidLibXrayLite возвращает дельты и сбрасывает native-счётчики при запросе, поэтому служба суммирует их и передаёт готовый снимок интерфейсу/уведомлению. Учитывается только outbound `proxy`: российский и локальный direct-трафик не включён. Временный сбой статистики не обнуляет значения, а помечает их задержку. Новый сеанс начинает счётчики с нуля. Анимации останавливаются в фоне и учитывают системное отключение анимаций.

**Плитка VPN в шторке.** Откройте **Настройки → Быстрое управление → Добавить плитку VPN в шторку**. На Android 13+ появится системное предложение добавить Reality VPN. На старых версиях используйте редактирование шторки (карандаш / «Изменить») и перенесите Reality VPN к активным плиткам. Плитка включает последний выбранный профиль и выключает работающий VPN. При первом запуске, отсутствии профиля или необходимости разрешений открывается приложение; системное разрешение VPN запрашивается штатно. На заблокированном телефоне сначала потребуется разблокировка.

**Постоянное уведомление.** Оно привязано к foreground VPN-службе, содержит счётчики, время сеанса и кнопку «Отключить VPN». Установлены флаги ongoing/no-clear; обычное «Очистить всё» не должно его удалять. Начиная с Android 14 система разрешает индивидуальный свайп даже для ongoing-уведомлений: приложение восстанавливает уведомление, пока соединение работает. Абсолютно запретить системное скрытие или отключение уведомлений пользователем нельзя. Разрешите уведомления Reality VPN в настройках Android, чтобы видеть их в шторке.

## Маршрутизация и хранение

- По умолчанию российские домены, `geosite:category-ru` и `geoip:ru` идут напрямую; локальные сети также напрямую.
- OpenAI/ChatGPT/OpenCode имеют явные proxy-правила перед российскими исключениями. На Android они применяются только к приложениям, включённым в VPN.
- Обычный DNS-трафик внутри туннеля обрабатывается Xray. По умолчанию запросы DoH направляются через сервер. На Android при включённом обходе РФ российские домены используют direct-DNS: DNS Wi-Fi/мобильной сети захватывается до создания VPN, резерв — `77.88.8.8` / `77.88.8.1`. Если обход РФ выключен, эти исключения не применяются. Это не отключает собственные DoH/DoT-механизмы браузеров и приложений.
- Windows: профили и сессия повышения прав зашифрованы DPAPI через Electron `safeStorage`; активный конфиг proxy-ядра временно хранится в каталоге текущего пользователя, TUN-конфиг — в административном runtime-каталоге. Файлы удаляются после штатной остановки.
- Android: AES-GCM, ключ в Android Keystore; резервное копирование профилей отключено. Удаление приложения удаляет локальные профили.
- Телеметрии и встроенных серверных доступов нет. Копирование VLESS-ссылки помещает секрет доступа в системный буфер обмена.
- Это не always-on kill switch: после остановки VPN обычное сетевое соединение восстанавливается. WFP-настройка Windows защищает DNS во время работы TUN, а не весь трафик после его остановки.

## Проверено в этой сборке

- TypeScript/Vue production build.
- Windows: 15 тестов импорта/валидации, конфигурации, проверки доступности, сохранения счётчиков при сбое и восстановления статистики, включения/выключения автозапуска и выбора правильного пути portable/установленной версии; read-only проверки native proxy API и запуска/мягкой остановки ядра в отдельной скрытой консоли.
- Playwright запускает упакованное Windows-приложение, импортирует тестовый профиль через UI, проверяет зашифрованное хранилище, запускает настоящий bundled Xray, читает его Stats API и отключает его. Недоступный тестовый сервер отображается жёлтым, а не зелёным. В тесте автоматическая настройка системного прокси выключена. Отдельная проверка запускает сам portable EXE дважды и убеждается, что повторный запуск не распаковывает файлы заново.
- Настоящий Xray `run -test` принимает proxy-, Windows TUN- и Android TUN-конфиги с упакованными geodata.
- Android: 13 тестов парсера/конфигурации, разделения DNS и порядка RU/AI/IP-правил, накопления native-дельт и скоростей, уведомления с трафиком и stop-action, системной декларации плитки и её команды отключения, фильтрации пакетов, значков приложений и отображения счётчиков; Robolectric проверяет также узкий экран 320 dp и увеличенный шрифт. Выполнены `assembleRelease`, `lintRelease`, `apksigner verify`, `zipalign -c -P 16`.
- Отдельный интеграционный тест запускает настоящий Windows Xray с DNS/routing-конфигурацией, сгенерированной Android-кодом, и локальными DNS/TLS-серверами. Он подтверждает TLS-соединения для `ya.ru` и `yandex.ru` через direct, когда тестовый VPN endpoint недоступен. Публичные сайты и реальный Android TUN в этом тесте не используются.

**Ещё нужна проверка с вашим сервером:** реальное Windows TUN-подключение/UAC, восстановление маршрутов после него, передача трафика и per-app правила на Android-устройстве. Windows smoke-тест не менял рабочий системный прокси и маршруты. Рабочий TUN на ПК с Kaspersky/корпоративными сетевыми политиками пока не подтверждён.

## Сборка Windows

Нужны Windows x64, Python 3, Node.js 22+ и штатный .NET Framework C# compiler.

Из корня репозитория:

```powershell
python vpn-client/scripts/prepare_windows.py
npm --prefix vpn-client/windows ci
npm --prefix vpn-client/windows test
npm --prefix vpn-client/windows run dist
npm --prefix vpn-client/windows run test:smoke
node vpn-client/windows/tests/portable-smoke.cjs
```

Скрипт скачивает Xray **26.11.9**, проверяет опубликованный digest, копирует geodata, компилирует `StopConsole.exe` и формирует integrity manifest. Для уже установленного Xray можно передать `XRAY_WINDOWS_DIR`, указывающий на папку `xray.exe`, `wintun.dll`, `geoip.dat` и `geosite.dat`.

`StopConsole.exe` отправляет CTRL+C отдельной консоли Xray, чтобы ядро успело убрать TUN-маршруты и WFP-фильтры. `RuntimeControl.exe` выполняет операции реестра/WinINET, UAC и запуск ядра без PowerShell и компиляции `Add-Type` при подключении. Elevated helper следит за родительским процессом и останавливает ядро при его завершении.

Команда `dist` сначала собирает NSIS-установщик и `win-unpacked`, затем `scripts/build_portable.py` собирает собственный загрузчик с кэшем. Для него используется `makensis.exe`, скачанный electron-builder; другой путь можно указать в `MAKENSIS`. Результаты тестового запуска portable сохраняются в `releases/windows/startup-benchmark-<версия>.json`.

## Сборка Android

Нужны JDK 17, Gradle 8.13, Android SDK platform 35 / build-tools 35.0.0. Android Studio не обязательна.

```powershell
python vpn-client/scripts/prepare_android.py
python vpn-client/scripts/create_android_key.py
```

Перед вызовом второго скрипта задайте `JAVA_HOME`. Он один раз создаёт `android/reality-client.jks` и `android/signing.properties`, исключённые из Git. **Сохраните оба файла в надёжном месте:** для обновления установленного APK нужен тот же ключ подписи. Скрипт не перезаписывает существующую подпись.

Из каталога `vpn-client/android`:

```powershell
gradle --no-daemon --console=plain testDebugUnitTest assembleRelease lintRelease
```

Для проверки разделения DNS через настоящий Xray на Windows после unit-тестов, из корня репозитория:

```powershell
python vpn-client/scripts/test_android_direct.py
```

Тесту нужны подготовленные Windows-ресурсы и Python-пакет `cryptography`; все DNS/TLS-соединения в нём локальные, системные прокси и маршруты не меняются.

Можно подготовить отдельный переносимый toolchain на Windows:

```powershell
python vpn-client/scripts/prepare_android.py --toolchain C:/build-tools/reality-android
```

Скрипт загружает JDK/Gradle/SDK, выводит пути `JAVA_HOME` и `ANDROID_HOME`, принимает лицензии SDK и устанавливает нужные пакеты. Библиотека `AndroidLibXrayLite v26.11.9` проверяется по закреплённому SHA256 из официального релиза. Вызов ядра: `CoreController.startLoop(config, tunFd)`; используется встроенный Xray TUN, без отдельного tun2socks.

После обеих сборок из корня репозитория:

```powershell
python vpn-client/scripts/collect_artifacts.py
```

Он копирует release APK в общую папку и пересчитывает `releases/checksums.json`.

## Зависимости и лицензии

- [Xray-core](https://github.com/XTLS/Xray-core), MPL-2.0; лицензия копируется рядом с Windows-ядром.
- [AndroidLibXrayLite](https://github.com/2dust/AndroidLibXrayLite), официальный AAR релиза 26.11.9, содержит Xray и Go mobile runtime.
- Electron, Vue, Lucide, grpc-js; версии npm закреплены в `windows/package-lock.json`.

Клиент находится в отдельном каталоге и не входит в серверный single-file installer.
